# غرفة التحكم - دربك (darbak-control-room)

برنامج ثالث مستقل عن تطبيق الراكب وتطبيق الكابتن، مهمته الوحيدة: إدارة تسعيرة خاصية
"النقل المشترك داخل المحافظة" (سعر الكيلومتر + سعر دقيقة الانتظار + الأجرة الأساسية).

أي تعديل تجريه هنا ينعكس تلقائيًا على التطبيقين لأنهما يسحبان التسعيرة من الخادم نفسه
كل ما فتح المستخدم شاشة "نقل مشترك داخل المحافظة".

## طريقة التشغيل

```bash
cd darbak-control-room
npm install
npm start
```

بعدها افتح المتصفح على:
```
http://localhost:4000
```

رح تشوف لوحة فيها 4 حقول:
- سعر الكيلومتر الواحد
- سعر دقيقة الانتظار
- الأجرة الأساسية
- الحد الأدنى للأجرة

لكي تحفظ أي تعديل يجب إدخال "مفتاح الإدارة" (Admin Key). الافتراضي هو:
```
darbak-2026
```
تقدر تغيّره بمتغيّر بيئة قبل التشغيل:
```bash
ADMIN_KEY=سرك-الخاص PORT=4000 npm start
```

## كيف تربط تطبيق الراكب وتطبيق الكابتن فيها

التطبيقين React Native (Expo) وبيشتغلوا على موبايل حقيقي أو محاكي، فما بيقدروا يوصلوا
لـ`localhost` تبع جهاز الكمبيوتر مباشرة. لازم:

1. شغّل غرفة التحكم على جهازك (لابتوب مثلاً) وتأكد إنه على نفس الشبكة (Wi-Fi) الموجود
   عليها الموبايل/المحاكي.
2. لاقي عنوان الـIP المحلي لجهازك (مثال: `192.168.1.10`). على ويندوز: `ipconfig`، على
   ماك/لينكس: `ifconfig` أو `ip a`.
3. افتح هذا الملف في مشروعي الراكب والكابتن وعدّل السطر الأول:
   - `darbak-passenger/src/lib/pricingApi.ts`
   - `darbak-captain/src/lib/pricingApi.ts`

```ts
export const CONTROL_ROOM_URL = 'http://192.168.1.10:4000'; // ← استبدله بعنوان جهازك
```

4. أعد تشغيل تطبيقي Expo (`npm start`).

إذا لم يتمكن التطبيق من الوصول إلى غرفة التحكم لأي سبب (مطفأ، بلا شبكة، ...)، فسيستمر بالعمل
بصورة طبيعية باستخدام تسعيرة افتراضية محفوظة داخل الكود (`DEFAULT_PRICING`) كي لا تتوقف تجربة
المستخدم.

## واجهة الـ API

- `GET /api/pricing` — يرجع التسعيرة الحالية (مفتوحة، بيستخدمها التطبيقين للقراءة فقط)
- `PUT /api/pricing` — تعديل التسعيرة (يحتاج Header باسم `x-admin-key`)

مثال جسم الطلب لـ PUT:
```json
{
  "baseFare": 0.5,
  "perKmRate": 0.15,
  "waitMinuteRate": 0.03,
  "minFare": 1
}
```

## ملاحظة مهمة

هذا نموذج أولي (Prototype) بسيط: يخزّن التسعيرة بملف JSON محلي على القرص، وما فيه نظام
مستخدمين حقيقي — مجرد مفتاح إداري واحد. لو رح تعتمده بالإنتاج الحقيقي، الخطوة التالية
المنطقية هي وضعه خلف قاعدة بيانات + نظام تسجيل دخول حقيقي للمشرفين + سجل تعديلات (audit log).
